## Findings considered and rejected

Recorded so nobody re-audits them next round:

- **`gitDir`/`GitCommonDir` probe sharing** — rejected: plan 033 already
  memoizes all three (`gitDirMemo`, `gitCommonDirMemo`,
  `worktreeGitDirMemo` in `internal/git/git.go:208-240`) keyed on cwd.
  Residue is at most one extra cold spawn per process; not worth a plan.
- **Windows/plan9 lock tests never execute** — `lock_access_windows_test.go`
  is build-tagged; `make vet-cross` compiles but doesn't run them, and the
  repo has no hosted CI by documented design. Adding a Windows CI leg is an
  infrastructure decision for the maintainer, not a code plan.
- **Cmd test-suite serialization (~8 min)** — real, but `t.Chdir`-based
  fixtures forbid `t.Parallel`, and restructuring to subprocesses is
  L-effort/high-risk for a `make ci`-gated repo. The practical mitigation
  (documenting `go test -run` subsetting + `ci-checks`) is inside plan 010.
- **God test files** (`cmd/commands_json_test.go`,
  `cmd/commands_mutation_test.go` — confirmed churn hotspots) — reorg is
  pure churn itself; merge-conflict pain is real but the fix would touch
  hundreds of test declarations for no behavior gain. Revisit if a rename
  or split is ever needed for another reason.
- **Agent-facing text surfaces under-pinned** (`st guide`, `undo --list`
  text output) — contains-level assertions are intentional; goldens already
  cover the high-traffic surfaces (help, log, status JSON). More pinning is
  brittleness, not coverage.
- **`install.sh` prerequisite completeness** (curl/tar/mktemp assumed) —
  the target platforms define these as universal; the explicit checks
  already cover the non-universal ones (`sha256sum`/`shasum`, `minisign`).
- **Release-signing doc ambiguity** (README says "transitional") — operator
  concern tied to plan-006-from-last-cycle's key provisioning; not a code
  finding.
- **`st sync` from a linked worktree leaves the worktree detached and
  unremovable by `st`** — narrow lifecycle leak, appears deliberate for
  cwd preservation; worth a docs note at most.
- **`st submit --dry-run` takes the write lock** — conservative, harmless;
  changing it trades safety for nothing an agent can observe.
- **Direction suggestions** (not plans — maintainer's call): `st create
  --parent <base>` for multi-worktree orchestration; a `st split` design
  spike; richer PR-prep read surface on top of `st commits`.
- **Rejected feature directions**: `absorb` handling non-tip commits
  directly (deliberate refusal); selective undo by label (cumulative
  snapshots already cover it); `st worktree mv` (rename ownership works);
  standalone swap/reorder (no demand signal); standalone `st show`/`st
  files` (subsumed by the read-surface direction).
